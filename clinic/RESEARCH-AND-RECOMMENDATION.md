# نظام حجز المرضى أونلاين — بحث وتوصية

**العيادة:** مستشفى كمال شعير — مركز الخصوبة وأمراض الذكورة
**الطبيب:** أ.د. أسامة كمال شعير — أستاذ طب وجراحة الذكورة، كلية الطب (القصر العيني)، جامعة القاهرة
**الفرع:** ٢١ شارع جابر إبن حيان — الدقي، الجيزة
**التاريخ:** أكتوبر ٢٠٢٦

---

## ١. الخلاصة التنفيذية

**التوصية:** نبني **واجهة حجز عربية/إنجليزية مستقلة** فوق **Easy!Appointments** (اللي اندمج في الريبو ده فعلًا)،
ونربطها بموقع **alrijal.com** القائم بدل أن نستبدله، ونترك **Vezeeta** كقناة اكتساب مفتوحة.
مش هنشتري منصة SaaS جاهزة، ومش هنلغي الحجز الحالي.

**سببان يحدّدان التوصية:**

1. **الحجز أونلاين موجود بالفعل** — والدفع كمان. صفحة `alrijal.com/shop` تبيع كشف الذكورة بـ $28
   والاستشارة الأونلاين بـ $50، بمواعيد عمل معلنة. المشكلة مش «إزاي نعمل حجز»،
   المشكلة إن الحجز **صفحة ووردبريس** بتطلب قفزة، مش تطبيق خفيف بيفتح في ثانية.
2. **سعة العيادة ضيّقة والفجوة فيها كبيرة.** المواعيد الثابتة ٣ أيام في الأسبوع، ٣ ساعات في اليوم
   (الأحد/الثلاثاء/الخميس، ١–٤ مساءً). سعة ١٢ يومًا في الشهر. أي no-show بيستهلك موعدًا
   نادر، مش merely inconvenience.

**مؤشر الأرقام:** بدائل السوق المصري بتتراوح بين **٦٩٩ و ٢٬٢٩٩ ج.م/شهر** ([1], [2]).
النظام الذاتي تكلفته الثابتة تقريبًا **خادم ٢٠٠–٤٠٠ ج.م/شهر + رسائل واتساب**، والباقي ملكية كاملة.

على عكس الحالة النموذجية، **البنية التحتية للحجز موجودة بالفعل**:

| الحقيقة | الأثر على التصميم |
| --- | --- |
| **الحجز والدفع موجودان على alrijal.com** | الواجهة الجديدة **تكملة لا بديل** — لازم تعمل مع نفس الخدمات والأسعار، لا تنافسها |
| **الأسعار منشورة بالدولار** | قاعدة مرضى دولية — النسخة الإنجليزية ليست رفاهية بل ضرورة |
| **سعة محدودة (٣ أيام × ٣ ساعات)** | أولوية للوقت، مش للوصول: تقليل الـ no-show أهم من زيادة الزيارات |
| **خدمة «كشف عاجل» خارج مواعيد العمل** | مسار منفصل تمامًا عن شبكة المواعيد |
| **حجز جراحة بعربون $500** | يحتاج مسار دفع وجدولة منفصل، مش شريحة في شبكة المواعيد |
| **حالتان على الأقل من أرقام الهاتف** | `01229999120` الحالي و`01006600606` المطبوع على أوراق ٢٠١٨ — كل رقم قديم رقم يوصّل لمكان مغلق |
| **التخصص حساس** | أي إشعار فيه اسم العيادة أو اسم التخصص = مشكلة. «الإشعارات السرّية» ليست رفاهية. |
| **الجمهور مصري ودولي، موبايل أولًا** | عربي RTL أساسي، إنجليزي أساسي، أرقام لاتينية، واتساب قناة التأكيد الطبيعية |

> الهدف مش «إلغاء Vezeeta»، الهدف **إن يكون عندك مكان مملوك للمريض حتى لو قالك يوم غلط**.

## ٤. ليه مش Vezeeta بس؟

لأن التخصص ده بالذات، **الحضور في ماركت بليس تبعية مش ملكية**:

- المنصة تتحكم في اسم الطبيب وشكل ظهوره وسعره — والسعر هو ورقة مفاوغة مع المريض.
- مفيش تحكم في مكان تخزين البيانات الصحية (نقل خارج مصر → يحتاج ترخيص PDPC).
- **العمولة على كل مريض جديدة بتاكل من هامش الاستشارة** — والاستشارة هنا وقت وعناية، مش سلعة.
- التقييمات الـ ٦٠٠ موجودة على المنصة، مش عندك. لو رحل، راحت معاك.

**البديل الصحيح:** وجود رقمي خاص على `osamashaeer.com` و`alrijal.com` — والسماح لـ Vezeeta
يجيب مرضى من برّه.

## ٦. ⚠️ الالتزام القانوني — ده مش تفصيلة

قانون حماية البيانات الشخصية المصري **رقم ١٥١ لسنة ٢٠٢٠**، ولائحته التنفيذية صادرة بقرار
رئيس الوزراء **رقم ٨١٦ لسنة ٢٠٢٥** (١ نوفمبر ٢٠٢٥، ونُشرت في الجريدة الرسمية ٢٥ ديسمبر ٢٠٢٥)،
وبدأت **فترة سماح سنة تنتهي ١ نوفمبر ٢٠٢٦** ([3], [4], [5]).

البيانات الصحية تُصنَّف **«بيانات شخصية حساسة»** (المادة ١٢). ومعناها عمليًا:

1. **ترخيص من مركز حماية البيانات الشخصية (PDPC)** قبل جمع/تخزين/معالجة البيانات الحساسة.
2. **موافقة صريحة مكتوبة** (ورقية أو إلكترونية) من صاحب البيانات — الإيماء أو الموافقة الضمنية **غير كافيين**.
3. الموافقة تكون **بالعربية**، منفصلة عن شروط الاستخدام، وبفعل إيجابي واضح.
4. **حق السحب والحذف والتصحيح** — ولازم يكون عندك سجل يثبت ده.
5. **ضوابط أمنية** معتمدة من المركز.
6. **نقل البيانات خارج مصر** يحتاج ترخيص أو تصريح منفصل + موافقة صاحب البيانات ([6]).

**الترجمة العملية للبناء:**

- كل حجز يسجّل: `نص الموافقة + رقم النسخة + التاريخ + IP` ← ده موجود في البروتوتايب.
- لو استضفنا على سيرفر **داخل مصر**، بنستغنى تمامًا عن إجراءات نقل البيانات للخارج.
- الاستضافة الذاتية (بدل SaaS أجنبي) بتقلّل سطح المخاطر بشكل جذري.
- **خطة الانتقال:** حجز global على Vercel = نقل بيانات صحية خارج مصر. للتشغيل الحقيقي،
  الخادم لازم يكون في مصر — والنسخة المنشورة على Vercel للعرض والتجربة فقط.

> ملاحظة: ده تلخيص هندسي مش استشارة قانونية. يُستحسن مراجعة محامٍ متخصص قبل التشغيل الفعلي،
> خصوصًا بند الترخيص من PDPC.

## ٧. تكلفة رسائل واتساب — بالأرقام

من **١ أكتوبر ٢٠٢٦** تغيّر تسعير Meta ([7], [8]):

- كل رقم بيزنس بياخد **١٠٠٠ رسالة خدمة مجانًا شهريًا**، وبعدها بتتحاسب.
- **قوالب Utility داخل نافذة ٢٤ ساعة بقت مدفوعة** (كانت مجانية).
- رسائل المريض الواردة لك **مجانية دايمًا**.

**تقدير لعيادة بـ ٤٠٠ موعد/شهر** (تأكيد + تذكير ٢٤ ساعة + تذكير ٣ ساعات ≈ ٣ رسائل/حجز ≈ ١٢٠٠ رسالة):

| البند | التقدير |
| --- | --- |
| أول ١٠٠٠ رسالة | مجاني |
| الـ ٢٠٠ الباقية | بسيطة (سعر السوق المصري من أرخص الفئات) |
| **الإجمالي** | **أقل من ٥٠ ج.م/شهر** |

مهما كان الرقم دقيق، هو **مش** اللي هيكسر الميزانية. اللي بيكسرها هو الاشتراكات الشهرية.

**ملاحظة خاصة بالحالة دي:** سعة العيادة ١٢ يوم عمل في الشهر، فالرسالة بتفيد مرتين —
بتأكّد الحجز **وبتتنادى حد في قائمة الانتظار** لما يتلغي موعد.

## ٨. القرار المعماري

```
┌──────────────────────────────────────────────┐
│  alrijal.com / osamashaeer.com (WordPress)   │
│  ← زر "احجز موعدك" يفتح /booking             │
│  (المسار الحالي يفضل شغّال جنبًا)            │
└───────────────────┬──────────────────────────┘
                    │
┌───────────────────▼──────────────────────────┐
│  واجهة الحجز (RTL + EN) — البروتوتايب        │
│  خدمة → يوم/وقت → بيانات → تأكيد             │
│  + مسار كشف عاجل + مسار عربون جراحة          │
└───────────────────┬──────────────────────────┘
                    │  REST (JSON)
┌───────────────────▼──────────────────────────┐
│  Easy!Appointments (PHP 8.2 + MySQL/MariaDB) │
│  • جدولة وساعات عمل • إلغاء/تأجيل            │
│  • سجل موافقات • Webhooks                    │
└───────┬───────────────────────────┬──────────┘
        │                           │
┌───────▼────────┐        ┌─────────▼──────────┐
│ واتساب Cloud   │        │ Google Calendar     │
│ API (تذكيرات)  │        │ + ICS للمريض        │
└────────────────┘        └────────────────────┘
```

- **الاستضافة:** VPS داخل مصر (أو خليجي قريب) — ٢ vCPU / 4GB تكفي بسهولة.
- **النسخ الاحتياطي:** يومي مشفّر، خارج نفس السيرفر، مع اختبار استرجاع شهري.
- **الأمان:** HTTPS إجباري، 2FA لحساب الإدارة، تحديث تلقائي، وتقييد الوصول لقاعدة البيانات.
- **التوازي:** الواجهة الجديدة تنشر كـ Preview على نفس الدومين (`/booking`) قبل ما تحلّ محل
  صفحة ووردبريس — مع قياس no-show قبل وبعد.

